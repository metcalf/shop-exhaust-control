# Process Notes

Lessons from running this project with a Claude supervisor and subagents, to carry into the dust collector project. Add an entry whenever something about the process works well or badly: a gate that caught a real problem, a subagent brief that was too vague, a phase that ate far more sessions than expected, a question that should have been asked earlier.

Format: date, phase, what happened, what to change.

---

- **2026-10-23, setup.** The kickoff docs said Andrew does HVLP spraying; he doesn't (aerosol cans only). The error drove a non-negotiable safety rule, a hardware spray bypass and a vapor-rated fan requirement. **Change:** in kickoff docs, mark facts about the owner and site as *stated* or *inferred*, and confirm inferred ones before building requirements or safety rules on them.
- **2026-10-24, setup (tooling, D-010).** Chose tools to make Claude's weak areas checkable instead of trusted: rendered schematic/board images, scripted netlist assertions against datasheets, creepage as a DRC rule. **Carry forward:** for the DC controller, reuse the netlist-assertion script and DRC rule file, and use the phase 3 Freerouting-vs-Quilter result to pick one layout path. *(Fill in the outcome after phase 3.)*
- **2026-10-25, phase 0→1.** The survey showed the fan's 120 V is switched by the lighting relay, so the fan dies when the lights go off. D-009 (vacant clear-down) had been accepted without knowing that. **Change:** for the DC project, the survey should ask early, for every load and every signal: how is it powered and switched today, and what turns it off? Check accepted behavior decisions against the answers before writing requirements.
- **2026-10-25, phase 1.** Putting thresholds in a parameter table (`P-nn`) with initial values and their sources let every AC be concrete enough to host-test now, while still leaving final values to commissioning. **Carry forward** to the DC project.
- **2026-10-25, phase 1.** The controller's location was accepted (Q-10) on convenience: near the work and the DC wiring. Only later did airflow direction show a mid-shop sensor is blind downstream (lathe, spraying), which moved everything to the north end and turned the DC link wireless. **Change:** for the DC project, and for any sensor placement, sketch the airflow path (inlets → outlets) and the source locations on the floor plan *before* asking where things go.
- **2026-10-25, tooling.** Added an unattended nightly run (`scripts/nightly.sh`, launchd at 22:00, AC-only, skips a dirty tree). It relies on `STATE.md` being the only handoff file, so the budget hook was changed to wrap up through the normal end-of-session steps. **Carry forward** to the DC repo. *(Fill in: did nightly runs do useful work while gates were pending, or mostly no-op?)*
- **2026-10-25, phase 1 (sourcing spot check).** A tight brief (numbered questions, "cite the datasheet section, say 'not found' rather than guess") got a usable SEN55/SPS30/SEN66 comparison with clear unknowns, at ~200k subagent tokens and ~9 min. It also turned up the SEN55's NRND status, which wasn't asked about directly but was covered by asking for lifecycle. **Carry forward:** always ask for lifecycle status in sourcing briefs.
- **2026-10-25, phase 2 (nightly).** The first unattended nightly run started phase 2. STATE.md said "when Andrew schedules it", and I took the nightly job itself as that scheduling, since G1 was recorded. The run produced the full G2 draft but **couldn't run the G2 reviewer**: subagents run in the background, and a nightly session closes when its turn ends. **Change:** either let the nightly prompt wait on one named subagent (the reviewer) before ending, or start the reviewer in the next attended session. For the DC repo, write next actions in STATE.md as unambiguous triggers ("start when G1 is recorded" rather than "when Andrew schedules it").
- **2026-10-25, phase 2.** Looking at the stock controller's PCB photo showed the fan cable is USB-C. That raised a hazard the requirements had missed: plugging the fan cable into the node's flashing USB would bypass the SR-09 isolation (D-020). **Carry forward:** for every external connector, check what happens if each cable is plugged into each port it physically fits.
- **2026-10-25, phase 2.** Design-level tunables were kept as `C-nn` in `docs/control-logic.md`, separate from the requirement-level `P-nn`, so the approved requirements didn't have to be reopened. **Carry forward.**
- **2026-10-26, tooling.** Fixed the nightly reviewer gap: the session now closes on an explicit done file rather than the first turn end, with an idle watchdog, and a PreToolUse hook refuses subagent spawns above 70% 5h usage. Spawn/finish usage is logged to `.claude/usage-log.tsv`. **Carry forward** to the DC repo. *(Fill in after a few reviewer runs: actual points per reviewer run, and whether 70% is right.)*
- **2026-10-26, phase 2 (G2 review).** The independent reviewer (~110k tokens, ~9 min) found three blocking issues the designer missed, including a self-contradiction between FR-06 and the `sensor_range` fault, and an SR-03 hole through resets that no single doc made visible. Applying Andrew's answers *before* the review meant it judged the current design rather than a stale one. **Carry forward:** apply pending answers, commit, then review; and for the DC project, check each "regardless of X" safety requirement against every reset path (OTA, panic, watchdog).
- **2026-10-28, phase 2 (Andrew, `docs/andrew-notes.md`).** The setup and docs feel heavy for something we'll iterate on. Clear requirements matter when Andrew isn't the one steering scope, but they cost a lot of time up front, and acceptance criteria weren't needed at the requirements phase. **Change for the DC project:** split hardware (get it right first time: full requirements, ACs and review for anything that shapes the board, enclosure or wiring) from firmware (specify only enough behavior to size the hardware, then implement and iterate in code with host tests; defer firmware ACs to implementation). Applied here from G2 on: firmware-only review findings become an implementation backlog, not doc revisions.
- **2026-10-28, phase 2→3.** Andrew moved pricing ahead of mech and firmware: schematic, then a priced parts list, then everything that depends on the parts (D-029). Part choices drive cost, assembler fees, board size and the enclosure, so sourcing last meant possible rework. **Carry forward** to the DC project's phase order.
